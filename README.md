# Mutrix

프로젝트의 코드 구조와 변경 크기를 탐색하는 로컬 분석 도구입니다. 폴더 → 파일 → 함수·클래스·메서드를 가로 Icicle 차트로 펼치며, 결과는 외부 서버 없이 열리는 단일 HTML입니다.

## 사용

Windows x64 실행 파일은 `dist/mutrix.exe`입니다. 분석할 프로젝트에서 실행합니다.

```powershell
E:\repos\mutrix\dist\mutrix.exe . --open
```

```powershell
mutrix.exe C:\projects\app `
  --base main `
  --output C:\reports\app.html `
  --json C:\reports\app.json `
  --summaries changes.json `
  --exclude "**/fixtures/**" `
  --open
```

| 인수                  | 동작                                                                             |
| --------------------- | -------------------------------------------------------------------------------- |
| `[path]`              | 분석할 폴더. 기본값은 현재 폴더이며 Git 저장소 안에서는 Git 루트부터 분석합니다. |
| `--base <ref>`        | 기준 브랜치 또는 커밋을 직접 지정합니다.                                         |
| `--output <path>`     | HTML 출력. 기본값은 지정 폴더의 `mutrix-report.html`입니다.                      |
| `--json <path>`       | 같은 분석 결과를 JSON으로 추가 출력합니다.                                       |
| `--summaries <path>`  | 노드별 설명 JSON을 보고서에 내장합니다.                                          |
| `--exclude <glob>`    | 제외 패턴을 추가합니다. 반복 지정할 수 있습니다.                                 |
| `--open`              | 생성한 보고서를 기본 브라우저에서 엽니다.                                        |
| `--help`, `--version` | 사용법·버전을 출력합니다.                                                        |

실행에는 Bun이나 Node가 필요하지 않습니다. Git 변경 비교에는 PATH에 Git이 있어야 합니다. 생성한 HTML은 다른 폴더나 컴퓨터로 옮겨도 Chromium 계열 브라우저에서 오프라인으로 열 수 있습니다. 경로 복사와 VS Code 링크는 보고서에 기록된 원래 프로젝트 경로를 사용합니다.

출력과 Summary 경로는 서로 달라야 합니다. 기존 Mutrix 보고서는 다시 생성할 수 있지만, 일반 소스 파일을 출력으로 지정하면 덮어쓰지 않고 오류로 종료합니다.

## 비교 기준

- 기준 자동 선택은 로컬 `master`, 로컬 `main`, `origin/master`, `origin/main` 순서입니다. 네트워크 fetch는 하지 않습니다.
- 기준 브랜치에서 실행하면 현재 작업 폴더의 구조를 표시합니다.
- 다른 브랜치에서는 기준과 HEAD의 **merge-base부터 현재 작업 폴더까지** 비교합니다. 커밋·스테이징·미커밋·신규 파일의 최종 내용을 포함합니다.
- 기준 브랜치만 새 커밋을 얻어도, 기능 브랜치의 분기점은 그대로 사용합니다.
- Git이 없거나 자동 기준이 없으면 구조 모드와 설명을 제공합니다. 잘못된 명시적 기준 또는 공통 조상이 없는 비교는 오류입니다.
- 프로젝트를 checkout하거나 파일·인덱스를 수정하지 않습니다. 생성 도중 편집을 계속하면 파일마다 읽은 시점이 다를 수 있으므로, 일관된 전체 스냅샷이 필요하면 편집을 멈추고 생성하세요.

## 라인 수와 차트

LOC는 주석·빈 줄을 포함한 물리적 줄 수입니다. 빈 파일은 0줄이고, 파일 끝 개행은 가상의 추가 줄을 만들지 않습니다. 줄 추가·삭제 비교에서는 CRLF/LF와 마지막 개행의 차이만 있는 경우를 제외합니다. 원본 내용 변경 상태는 유지합니다.

JS·JSX·TS·TSX·MJS·CJS·MTS·CTS에서는 클래스, 생성자, 메서드, 접근자, 함수 선언·표현식, 화살표 함수, 내부 중첩 함수를 분석합니다. 블록문과 인터페이스·타입 선언은 독립 스코프가 아니며 소유 스코프의 코드로 집계됩니다. 다른 UTF-8 텍스트는 파일 단위로 표시합니다. 구문 오류는 파일 LOC를 유지하고 스코프 분석만 생략합니다.

각 줄은 가장 깊은 스코프가 소유하고, 같은 줄에서 동률이면 소스상 먼저 등장한 스코프가 소유합니다. 부모 LOC는 자기 영역과 자식 영역의 합입니다. 상세 패널의 원본 줄 범위와 소유 LOC가 다를 수 있으며, 같은 줄의 짧은 심볼은 0 LOC여도 트리·검색에서 선택할 수 있습니다. 심볼 밖 영역은 `기타 코드`로 남깁니다.

구조 모드의 높이는 현재 LOC입니다. 변경 모드에서는 말단 영역별 전후 큰 값을 사용한 **비교 표시 LOC**로 삭제 영역도 보존합니다. 따라서 비교 높이는 실제 현재 LOC보다 클 수 있습니다. 필터와 부분 확대는 표시 범위의 높이를 다시 계산합니다.

| 표시                      | 의미                                                                            |
| ------------------------- | ------------------------------------------------------------------------------- |
| 초록                      | `(현재 LOC − 기준 LOC) / 기준 LOC`가 양수입니다. 증가율 100%에서 가장 진합니다. |
| 빨강                      | 같은 비율이 음수입니다. 감소율 100%에서 가장 진합니다.                          |
| 가장 진한 초록, `+∞`      | 새 영역입니다.                                                                  |
| 가장 진한 빨강, 잔존 `0%` | 삭제한 영역입니다.                                                              |
| 중립색과 테두리           | 내용은 수정했지만 순증감이 0입니다.                                             |
| 낮은 opacity              | 변경이 없습니다.                                                                |

추가·삭제 줄 수와 순증감은 별도 지표입니다. 이름이나 소속이 바뀐 심볼은 기존 ID와 대응할 수 없으므로 추가·삭제로 나타날 수 있습니다. 파일 이동은 구·신 경로에서 각각 집계하고 Git이 검출한 rename 관계로 연결합니다. 이동 자체도 해당 경로의 추가·삭제에 포함되며 프로젝트 전체 LOC 순증감은 상쇄됩니다.

파일·스코프를 클릭하면 상세 정보, 더블클릭하면 하위 영역을 봅니다. 배율 버튼을 누르면 `함께 / 가로 / 세로` 확대 축을 선택하고 각 축의 배율을 별도로 조절할 수 있습니다. 기본은 함께 확대하며, 가로·세로 배율이 다르면 두 값을 표시합니다. 함께 확대는 기존 비율을 유지하면서 두 축에 같은 배수를 적용합니다. 휠·핀치와 `+/−` 버튼은 선택한 축에 적용하며 글꼴·아이콘 크기는 유지합니다.

드래그로 이동하고, Shift+스크롤로 가로 이동합니다. 차트에 포커스한 상태에서 `+`, `-`로 선택 축을 확대·축소하고, `Home`이나 초기화 버튼으로 두 배율과 위치를 초기화할 수 있습니다. 트리·검색 결과는 Tab과 Enter로 선택하며 트리에서는 좌우 화살표로 펼치고 접습니다.

세로 높이가 2px 미만인 형제 영역은 LOD 집계 띠로 합쳐집니다. 가로 확대만으로는 집계를 해제하지 않습니다. 집계 띠의 증가·감소는 따로 표시하고 더블클릭하면 가로 폭을 유지하며 해당 띠를 세로로 확대합니다. 화면 밖 하위 트리는 그리지 않습니다. 미니맵은 두 배율에 맞는 표시 범위를 보여주며 클릭으로 화면 위치를 이동할 수 있습니다.

현재 영역을 나타내는 첫 열은 기본 줌에서 48px로 표시합니다. 하위 열의 기본 폭은 `200 → 180 → 160 → 140 → 120px`로 줄어들고 이후에는 120px을 유지합니다. 화면 크기에 맞춰 하위 열만 가로 배율을 적용합니다. 더블클릭으로 특정 영역에 들어가면 그 영역을 첫 열로 삼아 폭을 다시 계산하고 줌·이동을 초기화합니다. 들어간 노드를 다시 더블클릭하거나 뒤로가기를 누르면 직전 영역의 줌·이동 위치·필터·표시 모드를 복원합니다. 미니맵도 동일한 열 비율을 사용합니다.

## Summary JSON

```json
{
  "schemaVersion": 1,
  "entries": [
    {
      "nodeId": "file:src/parser.ts",
      "summary": "파싱 처리를 분리하고 중복 검증을 제거했습니다."
    },
    {
      "nodeId": "scope:src/parser.ts#function:parse~1",
      "summary": "블록 경계를 명시적으로 처리합니다."
    }
  ]
}
```

먼저 `--json`으로 결과를 얻고, JSON의 노드 ID를 사용해 설명을 작성한 뒤 `--summaries`로 다시 생성합니다. 폴더·파일·스코프 모두 설명을 붙일 수 있습니다. 보고서의 상세 패널에서도 ID를 복사할 수 있습니다. ID는 경로와 심볼 계층·종류·이름·동명 순서로 구성하고 줄 번호 이동만으로 바뀌지 않습니다. 익명 콜백이나 동명 심볼의 순서를 바꾸면 ID가 달라질 수 있습니다.

보고서의 **Summary 불러오기** 버튼도 같은 형식을 받습니다. 화면에서 불러온 설명은 해당 세션에만 반영합니다. 중복 ID는 첫 설명을 유지하고, 모르는 ID는 건너뛰며 각각 진단을 남깁니다. 설명은 HTML이 아닌 일반 텍스트로 출력합니다.

JSON 보고서는 `schemaVersion`, `meta`, `rootId`, `nodes`, `diagnostics`로 구성합니다. 노드는 `id`, `parentId`, `children`, 종류·경로·이름, 전후 줄 범위·LOC, `delta`, `added`, `removed`, `status`, `weight`, 선택적 `summary`·`rename`을 제공합니다. 소스 본문이나 AST는 HTML·JSON에 포함하지 않습니다. 분석 계약은 `src/shared/types.ts`에 있습니다.

## Codex로 PR 결과 확인

레포에 [mutrix-pr-review](.agents/skills/mutrix-pr-review/SKILL.md) 스킬이 포함되어 있습니다. `.agents/skills`는 [OpenAI 공식 문서](https://learn.chatgpt.com/docs/build-skills)의 레포 스킬 위치를 따릅니다. Codex에서 `$mutrix-pr-review로 이 PR의 결과를 확인하고 Summary가 붙은 HTML 보고서를 만들어줘`처럼 요청하면 사용합니다.

PR head·기준 ref 확인 → JSON 분석 → 실제 diff 검토 → 노드 ID로 Summary 작성 → HTML에 설명 내장 순서로 진행합니다. 미커밋 변경이 섞인 결과는 작업 폴더 스냅샷으로 구분하며, 리뷰 결과를 원격에 게시하지 않습니다. 다른 레포에서 쓰려면 `mutrix-pr-review` 폴더를 해당 레포의 `.agents/skills/` 또는 개인 스킬 폴더에 복사하고 Mutrix 실행 파일 경로를 알려주세요.

## 분석 대상과 v1 경계

Git 추적 파일과 Git이 무시하지 않는 신규 파일을 분석합니다. `.git`, `node_modules`, `vendor`, `dist`, `build`, `target`, `coverage`, `.next`, `.cache`, `artifacts`, `.venv`, `__pycache__`와 일반적인 lockfile은 기본 제외합니다. 추가 제외 규칙은 기준·현재 상태에 동일하게 적용합니다. 출력 HTML·JSON과 입력 Summary도 제외합니다. 심볼릭 링크·서브모듈 내부·바이너리·UTF-8로 해석할 수 없는 파일은 분석하지 않습니다. Git 저장소가 아닌 폴더에서는 기본 제외 규칙으로 폴더를 순회합니다.

v1은 리팩토링 점수나 자동 판정을 제공하지 않습니다. 다중 언어 AST, 실시간 감시, 전체 소스 diff 뷰, Explorer 직접 실행, 전용 데스크톱 창은 포함하지 않습니다. 삭제 노드는 원래 경로와 기준 범위를 표시하며 VS Code 열기를 비활성화합니다. 보고서는 생성 시점의 스냅샷이므로 새 변경은 다시 생성해야 합니다.

## 개발과 검증

UI·경로·노드 ID·차트 라벨은 모두 [SUIT](https://github.com/sun-typeface/SUIT) 가변 글꼴을 사용합니다. 글꼴은 HTML에 내장되어 오프라인으로 동작합니다. SUIT의 저작권 고지와 OFL 1.1 전문은 보고서의 diagnostics → Font license에서 확인할 수 있습니다. 표시 범위는 breadcrumb 옆 배지로, 현재 LOC는 차트 첫 열의 이름 옆에 표시합니다. 차트 조작 안내는 확대·축소 버튼 옆의 `?` 버튼에서 열 수 있습니다.

파일 아이콘은 [Simple Icons](https://github.com/simple-icons/simple-icons)의 필요한 SVG만 번들에 포함합니다. TSX·JSX는 React, TS·MTS·CTS는 TypeScript, JS 계열은 JavaScript이며 JSON·CSS·HTML·Markdown·Python·Go·YAML·TOML·Dockerfile·Svelte도 구분합니다. 트리·검색·상세 패널과 Canvas에서 같은 로고를 사용하고 차트의 변경 색상과 혼동되지 않도록 단색으로 표시합니다. 모든 아이콘은 HTML에 내장되며 Simple Icons 패키지는 CC0-1.0입니다.

현재 검증 환경은 Bun 1.3.6과 Windows x64입니다. 브라우저 자동 검증에만 Node와 설치된 Chromium 계열 브라우저가 추가로 필요합니다.

```powershell
bun install --frozen-lockfile
bun run dev
bun run typecheck
bun test tests
bun run format:check
bun run build
bun run demo
bun run verify:browser
bun run verify:exe
```

`build`는 뷰어를 먼저 빌드한 다음 HTML 템플릿을 내장한 exe를 생성합니다. `analyze`도 내장 템플릿을 사용하므로 먼저 `build:viewer`를 실행해야 합니다. 개발 서버와 `demo`는 설명용 합성 데이터를 표시하며 실제 저장소 분석 결과로 표시하지 않습니다.

브라우저 검증은 기본적으로 Windows Chrome을 사용합니다. 다른 실행 파일을 지정하려면 `$env:MUTRIX_BROWSER`에 절대 경로를 설정하세요. 외부 HTTP 요청을 차단한 상태에서 이동한 HTML, 검색·선택·필터·확대·Summary·테마·모바일을 확인하고, 정확히 10만 노드로 최초 표시 ≤5초·프레임 p95 ≤50ms를 검증합니다. 측정 환경과 결과는 `artifacts/verification.json`, exe 검증은 `artifacts/exe-verification.json`에 기록합니다.

모듈 경계는 `src/analysis`의 파일·Git·AST 분석, `src/shared`의 데이터·Summary·색상 계약, `src/report`의 HTML 직렬화, `src/cli`의 입력·출력·브라우저 실행, `src/viewer`의 탐색·레이아웃·Canvas 렌더링입니다. AST·Git 의존성은 프런트엔드 번들에 포함되지 않습니다.
